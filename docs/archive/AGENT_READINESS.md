## 6. Thread Network Agent Evaluation

### 6.1 Justification: Is a Dedicated Thread Agent Worth It?

**Answer: ❌ Not Yet (Can Fold Into Operations Agent)**

### 6.2 Thread-Specific Capabilities Available

| Capability | Data Source | Quality | Agent Utility |
| --- | --- | --- | --- |
| **Mesh Topology Visualization** | `GET /api/network/topology` | ✅ Complete (roles, parents, channels) | Agent can explain tree structure in words |
| **Node Role Classification** | ThreadRouteNode.role | ✅ Available (LEADER, ROUTER, END_DEVICE) | Agent can assess redundancy |
| **Reachability Detection** | Implicit (if in topology = reachable) | ⚠️ Indirect (no explicit "can reach" metric) | Agent can infer; not perfect |
| **Radio Quality Metrics** | GatewayHealth (channel, TX power, FER) | ⚠️ Gateway-only; not per-node | Limited granularity |
| **Multi-partition Detection** | GatewayHealth.partitionId | ⚠️ Only if multiple gateways exist | Advanced use case |

### 6.3 What's Missing for Robust Thread Agent

| Missing Feature | Impact on Agent | Workaround | Complexity |
| --- | --- | --- | --- |
| **Per-Node Signal Strength (RSSI)** | Cannot diagnose weak-link nodes | Infer from offline patterns | High |
| **Parent Change History** | Cannot detect thrashing (node rapidly re-parenting) | Monitor in application logic | High |
| **Packet Loss Rate Per Link** | Cannot identify flaky routes | Aggregate from sequence gaps | Medium |
| **Network Key Rotation History** | Cannot detect security events | Not applicable (fixed for this project) | N/A |
| **Extended Address Mapping** | Agent must store mesh ID ↔ node ID mapping | Already done in Node model | Low |

### 6.4 Recommendation

**Fold Thread diagnostics into the Operations Agent rather than create separate Thread Agent:**
- ✅ Simpler architecture (one agent, two modules)
- ✅ Agent can correlate Thread issues with alert patterns (e.g., "HIGH_CO2 alert coincides with node going OFFLINE")
- ✅ Thread-specific features added incrementally as backend improves
- ❌ Would be overkill to build dedicated Thread agent with current data richness

### Why This Agent Is Justified

1. **Rich API Surface:** 12+ REST endpoints provide comprehensive data access; no custom backend modifications required
2. **Mature ML Outputs:** IsolationForest anomaly scores + feature attribution provide interpretable context
3. **Persistent Alert Context:** XAI explanations and recommended actions embedded in database; agent can reason historically
4. **Real-Time Data:** WebSocket streaming enables reactive agent behavior
5. **Immediate ROI:** Reduces MTTR (Mean Time To Resolution) from 30 min → 5 min by automating root cause analysis
6. **Low Risk:** Agent augments existing alerts; doesn't replace deterministic thresholds
7. **Extensible:** Phases 2-3 can add Facility Intelligence and Advanced Diagnostics incrementally
